# Handoff 规范 Prompt（功能开发交接｜严格模板版）

## 1. 主 Prompt（可直接粘贴给 AI）

```text
你是本项目的高级工程师，请基于我提供的上下文，生成一份“功能开发交接（handoff）文档”。

【目标】
- 文档必须可审阅、可接手、可追踪。
- 面向项目内工程师，默认语言为中文。
- 仅针对“功能开发交接”，不是事故复盘。

【强约束（必须遵守）】
1) 必须遵循仓库 AGENTS.md 约束：
- Next.js 16 + App Router 约定
- app/features/components/lib 目录职责边界
- 最小化改动原则
- 提交前至少 lint（可运行时再 build）
2) 输出必须包含固定章节，且不得省略。
3) 如输入信息缺失，不得输出“完成版交接”；先输出“缺失信息清单”。
4) 每个关键结论都要给证据来源（命令输出 / 文件路径 / diff / 日志 / PR）。
5) 严禁输出敏感信息（token、密钥、隐私数据）；若输入含敏感信息，必须脱敏并标注“已脱敏”。
6) 不确定内容必须明确标记“假设”或“待确认”，禁止臆测。

【输入上下文】
我会提供以下字段（可能不完整）：
- 需求目标
- 变更摘要
- 关联 PR / Commit
- 关键文件列表
- 是否涉及 API / Schema 变更
- 已知风险
- 验证记录（lint / build / 手测）
- 附件链接（文档、日志、看板）

【信息完整性检查规则】
- 若缺少以下任一关键字段，先输出“缺失信息清单”：
  - 需求目标
  - 变更摘要
  - 关键文件列表
  - 验证记录（至少 lint 或等价检查）
- 若声称“涉及 API/Schema 变更”，但缺少兼容性说明或迁移说明，也必须进入“缺失信息清单”。

【输出格式（严格按此结构）】
# 缺失信息清单（如信息齐全则写“无”）
- ...

# 交接摘要
- 用 1~3 句话说明“做了什么、为什么做、当前状态”。

# 范围与影响
## In Scope
- ...
## Out of Scope
- ...
## 影响模块
- ...

# 实现细节
- 关键设计与实现路径
- 与现有架构一致性（尤其是 Next.js 16 / App Router / Server-Client 边界）
- 主要 trade-off

# 接口与数据变更
## API 变更
- 无 / 有（列出 endpoint、请求/响应变化、兼容性）
## 类型与 Schema 变更
- 无 / 有（列出字段变化、默认值、迁移策略）
## 兼容性与迁移说明
- 无 / 有（必须可执行）

# 验证与证据
## 自动化检查
- lint: 命令、结果、时间
- build: 命令、结果、时间（若未执行需写原因）
## 手动验证场景
- 场景1：步骤、预期、结果
- 场景2：步骤、预期、结果
## 证据索引
- 文件: <path>
- diff/PR: <link>
- 日志: <link or 摘要>

# 风险与回滚
## 已知风险
- 风险项、触发条件、影响面
## 回滚方案
- 回滚前提
- 操作步骤
- 回滚后验证

# 待办与责任人
- [P0/P1/P2] 事项 | Owner | 截止时间 | 阻塞项

# 附件索引
- 文档：...
- PR：...
- 看板/Issue：...

【风格要求】
- 表达简洁、工程化、可执行。
- 不写空话，不写与本次改动无关内容。
- 若“缺失信息清单”非“无”，在文末追加“当前结论置信度：低”。
- 若信息完整，文末追加“当前结论置信度：中/高（给出依据）”。
```

## 2. 输入示例（给团队成员填写）

```md
## 需求目标
为编辑器增加“模板预览弹窗”能力，支持在列表页直接查看模板详情后再创建文稿。

## 变更摘要
- 新增模板预览弹窗组件与触发入口。
- 调整模板列表交互流程，创建前增加确认步骤。
- 补充模板预览 API 返回字段映射。

## 关联 PR / Commit
- PR: https://github.com/org/repo/pull/123
- Commit: abcdef1, abcdef2

## 关键文件列表
- app/templates/page.tsx
- features/template/components/template-preview-dialog.tsx
- features/template/components/template-list-client.tsx
- app/api/templates/[templateId]/preview/route.ts

## 是否涉及 API / Schema 变更
- API: 是（`GET /api/templates/[templateId]/preview` 增加 `slidesCount` 字段）
- Schema: 否

## 已知风险
- 模板数据为空时弹窗兜底展示可能不完整。

## 验证记录
- lint: `bun run lint` 通过（2026-04-03 15:20 CST）
- build: 未执行（本次仅 UI 变更，先做开发态验证）
- 手测:
  - 模板列表点击“预览”可打开弹窗
  - 关闭弹窗后列表滚动位置保持
  - 预览后点击“使用模板”可正常建稿

## 附件链接
- 设计稿: https://xxx
- 测试记录: https://xxx
```

## 4. 验证样例（用于检验 Prompt 质量）

### Case A：仅前端改动
- 期望：必须输出架构影响、Server/Client 边界、手测结果。

### Case B：含 API/Schema 变更
- 期望：必须输出兼容性与迁移说明；缺失则进入“缺失信息清单”。

### Case C：信息不全
- 期望：先输出“缺失信息清单”，且不产出伪完整结论。

### Case D：含敏感字符串
- 期望：自动脱敏并标注“已脱敏”；不得回显原文。
